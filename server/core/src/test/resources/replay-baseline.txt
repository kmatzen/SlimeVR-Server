# skeleton replay baseline
# key  value  tolerance
#
# Covers both configurations: the plain solver, and the solver with the leg
# corrections engaged (the `+legtweaks` keys). Replay of both is now
# bit-reproducible -- LegTweaksBuffer takes its frame times from an injected
# FrameClock rather than System.nanoTime() -- so the measured run-to-run spread
# is zero and tight tolerances are legitimate.
#
# On why so many `+legtweaks` values are zero: the corrections fully eliminate
# the artifacts these metrics measure on clean synthetic input. That was
# verified rather than assumed. For `squat`, the left ankle goes from a minimum
# of -0.2339 m (clipping through the floor on every one of 400 frames) to a
# minimum of ~0 and a maximum of 0.0129 m, still planted on all 400 frames,
# while horizontal travel during planted frames falls from 0.2012 m to 0. For
# `walk-in-place`, planted frames and ankle heights are unchanged -- there is no
# clipping to fix -- while horizontal travel during planted frames falls from
# 0.8835 m to 0. The feet are being locked, not lifted out of the measured
# region.
#
# The consequence is worth knowing when reading a diff here: these zero lines
# gate "the corrections still work at all", and any nonzero value is a
# regression. They cannot express "slightly worse", because there is no headroom
# left on synthetic input.
#
# `segment_deformation_*` is the exception, and it is why those keys are here.
# Every other metric asks whether the output is in the right *place*; these ask
# whether it is a body. A skeleton has fixed segment lengths and forward
# kinematics cannot violate them -- which is why the plain-solver rows read
# exactly 0.000000, and that is the metric's own calibration rather than a
# result. `LegTweaks` translates the ankle, the knee and the hip independently,
# and independent translations of a segment's endpoints change its length.
#
# So the corrections drive slide and clip to zero *by* deforming the skeleton,
# and the frames where those read zero are the frames where this reads largest:
# 0.161902 m on `squat`, 11.4% of a segment. The residual did not go away when
# the other columns hit zero, it moved into a channel nobody was measuring.
#
# That makes these the one set of keys on synthetic input with headroom to
# express degradation rather than only breakage. A change to the leg path that
# made it meaningfully worse but still nominally functional moves them.
# Everything else still needs recordings with real sensor noise and drift --
# see issue #15 -- and this narrows what those recordings are needed *for*.
#
# Regenerating this file is how a real regression gets blessed as expected
# behaviour. Read the diff first.
#
#   ./gradlew :server:core:test --tests 'dev.slimevr.replay.SkeletonReplayTest' \
#       -Dreplay.writeBaseline=true
